## Design Specificity Verdict

**The system is authored for this product. The composition on screen is not.**

The tokens, the phase channel and the two-channel state encoding are genuinely specific. But the screenshot shows the canvas at 1.8% occupancy: one lane, one node, and a 440px card that covers the very node it grew from (`TaskNode.module.css` sets the node's children to `opacity: 0` when expanded).

**Deterministic scan** — `detect.mjs` exit 2, 28 findings: 24 `design-system-font-size`, 2 `design-system-radius` (3px in `Markdown.module.css:30`, 2px in `TabChip.module.css:12`), 2 `side-tab`.

**The 2 `side-tab` findings are false positives.** They flag `border-left: 4px solid var(--phase)` on `TaskNode` and `NodeCard` — DESIGN.md's own Left Edge Rule, applied to exactly the two surfaces it governs.

**No browser overlay available** — no browser automation tool in this session's surface. All measurements computed from source.

## What's Working

1. **`selectors/status.ts` is architecture, not style.** One pure function every surface calls, so "never show a raw agent state" is impossible to violate.
2. **The phase channel.** Four rules in `base.css` are the entire system; four components read `var(--phase)` and none knows what a phase is.
3. **The attention chip.** `go()` adds to desk, switches view, expands, pans at `maxZoom: 1.2`. The RTS promise actually delivered.

## Priority Issues

### [P0] One decision renders twice, with divergent drafts and a race to submit

`NodeCard` mounts `DecisionCard` → `QuestionPrompt`; `Transcript.tsx:51` mounts `QuestionPrompt` independently. Same `requestId`, two `useState` drafts. Visible in the screenshot: panel copy has "Other" filled, card copy has nothing selected. The daemon resolves on the first answer received.
**Fix:** one `requestId` → one live prompt, enforced in a selector.

### [P0] No task node is reachable from the keyboard

`TaskNode.tsx` renders a bare `<div>` — no `tabIndex`, no `role`, no `onKeyDown`. `Canvas.tsx` binds expansion solely to `onNodeClick`. Four keydown handlers in all of `src/`. WCAG 2.1.1 failure on the primary control.

### [P0] Light scheme fails AA on six hues; `--fg-faint` fails in dark everywhere

`--fg-faint` 3.36 dark / 4.47 light. `--hue-attention` 3.69, `--hue-land` 3.43, `--hue-build` 3.75, `--hue-ok` 4.00, `--hue-accent` 4.46 (light). `--border` 1.41 dark / 1.28 light against a 3:1 requirement. 22 `--fg-faint` declarations fail in dark.

### [P1] Raw `AskUserQuestion` JSON dumped above its own rendered form

`classifyToolCall` handles Bash/Edit/Write/Read; everything else hits `generic` → `JSON.stringify`, expanded by default. `selectors/transcript.ts`'s `contextBefore` already skips this exact item.
**Fix:** skip `QUESTION_TOOL`/`PLAN_TOOL` tool_calls in `Transcript.tsx`. UI layer only — do not touch `normalise.ts` (Python parity + goldens).

### [P1] `Stop` is the quietest control on the card

`Stop` uses `.quiet` → `--fg-muted`; `Launch` beside it uses `.primary`. No confirmation, weight, or undo on either `Stop` or plan `Approve`. Risk gradient inverted.

### [P2] Type scale collapses; DESIGN.md doesn't match code

`tokens.css` ships 11/12/13/15; `DESIGN.md:405` sets a 14px body and a 12px floor. 21 of 37 hardcoded font-sizes sit below that floor, incl. 9px at `TaskNode.module.css:72`. Nine interactive elements under the WCAG 2.2 24×24 minimum.

## Persona Red Flags

**Alex (power user):** Cannot Tab to a node and open it. Attention chip is the only keyboard route to a decision. `MessageInput` sends on bare Enter with no Cmd+Enter alternative.

**Sam (accessibility-dependent):** Canvas nodes are unlabelled `<div>`s (4.1.2). `role="dialog"` on `NodeCard` with no focus trap, no initial focus, no focus restore. Option selection is a ~1.1:1 wash. No live region on state change.

**The Flipper:** Nothing survives a flip — drafts live in unmounting component state. `NodeCard`'s `ResizeObserver` re-pans the viewport on every transcript append, breaking DESIGN.md's Fixed Board Rule.

## Minor Observations

- `CARD_CENTRE_Y = 140` off by 5× for tall cards.
- `SessionTab` scrolls to bottom on every append with no scrolled-up guard.
- `.otherInput` is single-line; long answers unreadable.
- React Flow watermark unconfigured.
- `AttentionChip` aria-label describes a count, not the navigation it performs.
- Zero layout media queries and zero container queries.

## Questions to Consider

1. Would a fixed command region serve the RTS metaphor better than an in-place card?
2. The panel is "where the user reads" — so why can the user answer, deny, approve and stop from inside it?
3. `contextBefore` curates a wait into a narrative; `Transcript` renders it as a raw log. What is the session tab for?

## Decisions taken

- Canvas composition: **keep the in-place card.** It keeps focus around the node when making small adjustments to several of them. The sidebar is for deeper work only — opening a console or a document.
- Type scale: raise the code to the doc's 14px body and 12px floor.
- Scope: the three P0s plus the two P1s.
- Shipped on this branch: the duplicate live prompt (P0-1) and the raw
  `AskUserQuestion` dump (P1-1). Still open: keyboard reach (P0-2), contrast
  (P0-3), `Stop`'s weight (P1-2), and the type scale (P2).
